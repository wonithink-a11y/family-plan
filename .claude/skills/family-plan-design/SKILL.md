# 패밀리 플랜 디자인 스킬

화면이 달라지는 작업은 이 순서로 한다. 코드부터 쓰지 않는다.

## 0. 디자인 방향 (허남원님 결정, 2026-11-17 변경)

- **A안 "벤토 다크 글라스" 하나로 통일한다.** 앱 화면(우리집·일정·수행평가·설정, 폰과 태블릿)은 모두 A안: 어두운 바탕, 반투명 유리 카드가 격자로 놓이고 카드 크기가 정보 중요도를 말한다.
- **C안의 요소**(큰 시계, 음성 구슬, 도장 동그라미)는 A안 화면 안의 부품으로 쓴다. 우리집 화면이 그 예.
- **벽걸이(`?view=wall`)와 루미 음성 화면**은 같은 A안 토큰을 쓰되 **멀리서 읽히는 큰 글자와 3칸 배치**만 다르다(스타일이 아니라 용도 차이). 스타일을 따로 만들지 않는다.
- 시안은 캔버스(`https://claude.ai/artifact/EbABNSiwVAvJRs5TDNyMjN`, 작성자만 열람)에 있다. 접근할 수 없으면 아래 토큰만으로 만든다.
- 라이트 모드도 지원한다(자동 전환). 라이트는 기존 `:root` 변수(`--bg`, `--card`, `--text`, `--muted`, `--border`)를 따르고 다크는 `[data-theme=dark]`로 덮는다.
- 적용 현황: 우리집, 일정(달력·목록), 수행평가(목록·통계), 설정, 가이드는 A안 적용 완료. 벽걸이도 적용. 루미 시트도 적용. 웰컴 화면·입력 시트도 적용(이모지 라벨은 후속). 날씨 아이콘은 SVG.
- 방향을 바꾸려면 먼저 허남원님께 묻는다(`CLAUDE.md` 제품 결정).

## 1. 먼저 정할 것 (코드 전에 한 줄씩)

- 누가, 어디서, 얼마나 떨어져서 보나: 딸(중1)이 폰·태블릿을 손에 들고 / 가족이 거실 벽 태블릿을 서서 본다.
- 이 화면이 하는 일 하나: 확인(읽기), 체크(누르기), 말하기(음성) 중 무엇인가. 한 화면의 주 동작은 하나로 둔다.
- 비워 둘 정보: 한 화면에 다 넣으려 하지 않는다(가로 태블릿 한 화면 규칙은 아래 5).

## 2. 토큰 (다크 기준, 시안에서 쓴 값)

| 용도 | 값 | 비고 |
|---|---|---|
| 바탕 | `#0A0E1F`(앱), `#0E1220`(벽걸이) | 순수 검정·흰색 금지 |
| 카드 | `rgba(255,255,255,.07)` + 테두리 `rgba(255,255,255,.12)` | `backdrop-filter: blur(16px)`는 카드에만 |
| 글자 | `#ECEEF8`, 보조 `#A9B1D6` | 보조도 대비 4.5:1 이상 |
| 강조(주) | `#818CF8`(인디고), 보라 `#C9C1E4`(C안) | 버튼 글자는 어두운 색 |
| 성공 | `#22C55E` | 체크, 동기화 |
| 주의/위험 | `#FB923C` / `#F87171` | D-day 배지: 오늘=위험, D-3=주의 |
| 글꼴 | `Noto Sans KR`, 굵기 300(큰 숫자)·500·700 | 본문 최소 14px, 보조 최소 12px, 줄 높이 1.5 |
| 모서리 | 카드 24px, 버튼 14px, 배지 10px | 한 화면에서 단계를 3개 이하로 |
| 간격 | 4의 배수(8·12·16·24) | 카드 사이 12px |

새 색을 만들면 `:root` 변수로 올리고, 화면 코드에 hex를 직접 쓰지 않는다. 변수에 이름이 있으면 그걸 쓴다.

## 3. 만드는 순서 (AI 티가 나는 기본값 걷어내기)

간격 → 색 → 아이콘 → 문구 → 글자 → 배치 → 디테일 → 움직임 순서로 손본다. 앞 단계가 맞아야 뒤 단계가 의미가 있다.

1. **간격**: 4의 배수 하나의 체계만 쓴다. 카드 안 여백이 카드마다 다르면 틀린 것이다.
2. **색**: 강조색은 화면당 하나(+상태색). 모든 카드에 그라데이션·그림자를 넣지 않는다. 가장 중요한 카드 하나만 눈에 띄게 한다.
3. **아이콘**: 선 아이콘(SVG, 두께 일정) 하나의 세트. 새 화면은 이모지를 쓰지 않는다(기존 하단 메뉴 이모지는 놔둔다). 아이콘만 있는 버튼에는 `aria-label`.
4. **문구**: 짧고 담담하게, 느낌표·과장 금지. 딸이 읽는 말투(중1 수준). 안 쓰는 설명 문구는 지운다.
5. **글자**: 크기는 3~4단계만. 큰 숫자(시계, 온도, 도장)는 얇게(300), 제목은 500~700.
6. **배치**: 카드 크기로 중요도를 말한다. 비슷한 것은 같은 카드 모양, 다른 것은 다른 모양. 왼쪽 선 카드(예전 수행평가·일정 카드의 색 막대는 제거함), 모든 것이 같은 크기의 카드 나열은 피한다.
7. **디테일**: 눌렀을 때 반응(색 변화·눌림), 빈 상태 문구, 로딩, 오류 표시를 같이 만든다.
8. **움직임**: 150~300ms, 의미 있는 변화에만. `prefers-reduced-motion`이면 끈다. 깜박임·계속 도는 장식 금지(음성 듣는 중·말하는 중 표시는 예외).

## 4. 반드시 지킬 것 (이 앱에서 사고가 났거나 날 수 있는 것)

- **터치 크기 44px 이상**(체크, 버튼, 메뉴, 도장 찍기). 눌러야 하는 것 사이 간격 8px 이상.
- **글자 대비 4.5:1 이상**. 12px 보조 글자도 포함. 큰 글자(24px+)는 3:1.
- **색만으로 구분하지 않는다**: D-day 배지는 색 + 글자(`오늘!`, `D-3`), 상태는 색 + 아이콘/글자.
- **실제 `<button>`, `<a href>`**. `div`에 `onclick`만 붙여 버튼처럼 쓰지 않는다(기존 코드는 인라인 `onclick`이 많으므로 새 코드부터).
- **다크 모드를 같이 만든다**: 새 컴포넌트는 `var(--card)`, `var(--text)`, `var(--border)` 같은 변수를 쓰거나 `[data-theme=dark]` 규칙을 함께 추가한다. 한 번 흰 카드가 남아 글자가 안 보인 적이 있다.
- **`!important` 주의**: `.screen`의 아래 여백이 `!important`라 덮을 때 같은 우선순위가 필요하다.
- **다크 모드 규칙 순서**: 앞쪽에 `[data-theme=dark] .bk-section,.evt-card,...{background:var(--card)}` 같은 옛 규칙이 있어, 같은 점수의 새 규칙을 앞에 쓰면 진다. 새 다크 규칙은 `:root[data-theme=dark] ...`로 쓰거나 파일 끝 보정 블록에 둔다.
- 날짜는 `toISOString()` 금지(CLAUDE.md 규칙 2). `KR_HOL`, `EVT_CATS` 삭제 금지.
- 서비스워커 캐시 이름(`sw.js` `CACHE_NAME`)과 `APP_VER`를 올린다.

## 5. 화면 크기와 확인

반드시 이 크기로 본다. 한 번에 모아서 보고, 고친 뒤 다시 본다(고칠 때마다 보지 않는다).

| 크기 | 뜻 | 기준 |
|---|---|---|
| 1138×712 | 갤럭시 탭 S8+ 가로(주 화면) | **스크롤 없이 한 화면**(우리집, 벽걸이). 넘치면 카드 안에서만 스크롤 |
| 1280×800 | 큰 태블릿 가로 | 위와 같음 |
| 390×844 | 폰 | 1열, 하단 메뉴 |
| 다크/라이트 둘 다 | | 흰 카드 잔상, 글자 안 보임 확인 |

- 확인 방법: `dev/` 테스트(가짜 Firestore)와 헤드리스 Chrome 캡처. "검증됨"은 실기기에서 본 것에만 쓰고, 캡처로 본 것은 "가짜 서버 기준 캡처"라고 적는다.
- 화면 크기가 줄었을 때 잘리는 것은 `scrollHeight`와 `clientHeight`로 숫자로 확인한다(`dev/members-test.js`의 벽걸이 잘림 검사 참고).

## 6. 하지 않을 것

- 글로우를 모든 곳에 쓰기, 반짝이는 배경 장식, 이유 없는 그라데이션 글자.
- 라벨마다 이모지, 느낌표 가득한 문구, 만화 같은 일러스트(초등학생 앱처럼 보이면 실패).
- 한 화면에 카드 모양을 여섯 가지 이상 쓰기.
- 새 라이브러리·폰트·이미지를 CDN에서 추가하기(빌드 없는 단일 파일 앱이다. 폰트는 기존 방식 유지).
- 디자인 방향(색 체계, 도장 규칙, 이모지 규칙)을 허락 없이 바꾸기.
