## Firestore 데이터 구조 (모두 `families/{가족코드}/` 아래)
- `meta/reward` : `{stampCount, couponsIssued, pinHash}`
- `meta/routine` : `{items:[{id,text}]}` (없으면 기본 5개 항목)
- `routine/{YYYY-MM-DD}` : `{date, done:{항목id:true}, stamped}`
- `stamps/{id}` : `{id, date, reason, ts}` (루틴 도장 id는 `rt_{날짜}` → 중복 불가)
- `coupons/{id}` : `{id:'cp1', no, title, issuedAt, usedAt}`
- `preps/{id}` : `{id, date, text, ts, by, done}`

도장 +1과 구입권 발급은 `db.runTransaction` 안에서 처리합니다(`applyStamp`). 두 기기에서 동시에 찍어도 구입권은 `cp{발급순번}` 한 장만 생깁니다.

## 키와 설정 (기기마다)
- 설정·키는 **그 기기의 localStorage에만** 저장하고 Firestore에는 올리지 않습니다 (`fp_assist_cfg`).
- 가든 앱(`wonithink-a11y.github.io/garden`)과 **같은 주소(origin)** 라서, 같은 브라우저에 가든 앱 키(`kma_api_key`, `gemini_api_key`)가 있으면 그대로 읽어 씁니다. 가든 앱은 기상청 키를 JSON 문자열로 저장하므로 읽을 때 따옴표를 벗겨 씁니다 (`asLsKey`).
- 설치형 앱(PWA)이 브라우저와 저장소를 따로 쓰는 기기에서는 우리집 탭 → "음성·AI·날씨 설정"에 한 번 직접 넣어야 합니다.
- ⚠️ Gemini 키는 브라우저에 노출되는 구조입니다(가든 앱과 같은 방식). Google AI Studio/Cloud 콘솔에서 키를 `wonithink-a11y.github.io` 웹사이트로 제한하는 것을 권장합니다.

## 음성 관련 사실과 한계
- **음성 인식**은 크롬 계열(안드로이드 크롬·삼성 인터넷)에서 동작하고 인터넷이 필요합니다. 마이크 허용이 필요하며, 지원하지 않는 브라우저는 글자 입력 칸을 안내합니다. 호출어(“헤이 ○○”)로 항상 듣는 방식은 웹앱에서 안정적으로 불가능해 **버튼을 눌러 말하는 방식**입니다.
- **자동 브리핑(벽걸이)**: 브라우저는 사용자가 한 번 화면을 터치하기 전에는 소리를 내지 못합니다. 지정 시각이 되었는데 터치가 없었다면 화면에 "터치하면 브리핑을 들려드려요" 안내가 뜨고, 터치하는 순간 재생됩니다. 앱을 새로 열면 하루 한 번 터치가 필요합니다.
- **Gemini TTS 모델 이름은 자주 바뀝니다.** 현재 순서: `gemini-3.8-flash-tts`(새 요청 형식) → `gemini-3.1-flash-tts-preview` → `gemini-2.5-flash-preview-tts`. 404면 다음 모델로 넘어가고 마지막에 성공한 모델을 기억합니다. 모두 실패하면 기기 음성으로 읽습니다. 요청 형식은 Google 문서 기준으로 작성했고, **실제 키로 호출해 보지는 못했습니다**(이 환경에서 외부 접속 불가) — 테스트는 가짜 응답으로 했습니다.
- 무료 사용량 한도에 걸리면 기기 음성으로 대체하고 사유를 화면에 표시합니다. 사용량을 아끼려면 설정에서 "기기 음성만"을 고르세요.
- **Claude 앱 연결**: 웹앱이 같은 태블릿의 Claude 앱을 직접 호출하는 방법은 없습니다. 대신 ① 문제은행 아티팩트(AI 선생님)로 가는 버튼, ② 답변 화면의 "공유·복사"(공유 시트에서 다른 앱 선택) 를 넣었습니다. Claude API를 앱에서 직접 부르려면 키가 노출되고 비용이 발생해 권하지 않습니다.
- **문제은행 데이터 연동은 하지 않았습니다.** 문제은행은 별도 앱(`/exam/`)이고 기록 구조가 달라, 이 앱에서는 열기 버튼만 둡니다. 오답 개수 가져오기 같은 연동은 문제은행 쪽에 공유 형식을 만든 뒤에 가능합니다.

## 말 해석 규칙 (`asParse`)
- 과목명 + 날짜 표현(오늘·내일·모레·N일 뒤·이번/다음 주 ○요일·○월 ○일·○일까지)이 있고 “수행”이 들어가거나 제출·마감·발표 등이 있으면 **수행평가 등록**, “준비물·가져가야·챙겨야”가 있으면 **준비물 요청**, “브리핑·날씨·우산·오늘 뭐 있어”는 **브리핑**, 수행평가 + 질문어(뭐·언제·알려)는 **조회**, 나머지는 **AI 질문**.
- 등록은 항상 확인 카드(과목·날짜·내용·배점 수정 가능)를 거칩니다. 음성 오인식이 그대로 저장되지 않게 하려는 의도입니다.
- 해석하지 못하는 것: “내일모레”(= 모레로 처리 안 됨), 한글 숫자(“삼 일 뒤”), 한 문장에 수행평가 여러 개. 실패하면 확인 카드에 빈칸으로 나옵니다. 정확도를 높이려면 이 단계에 Gemini 해석을 추가하면 됩니다(다음 할 일).

## 루미(가족 음성 비서) 1~3단계 (2026-11-17)

호칭은 기본 **루미**, 설정 ⚙ → "비서 이름"에서 언제든 변경(저장 시 시스템 지침·화면 제목·호출어에 모두 반영).

### 1단계 — 대화 + 도구 호출 (index.html `루미 1단계` 블록)
- 마이크 버튼 = 연속 대화: 듣기 → 생각 → 읽어 주기 → 다시 듣기. 말이 두 번 연속 없거나 "그만/종료"라고 하면 종료. 말하는 중 마이크를 누르면 끊고 바로 듣기.
- Gemini 함수 호출로 앱 데이터를 직접 조회: `get_today_info, list_assessments, list_preps, list_events, get_weather, get_routine_status, resolve_date`.
- 쓰기 `add_assessment, reschedule_assessment, mark_assessment_done, add_prep` 는 **바로 저장하지 않고 확인 대기**. 실행 경로는 ① 화면 [확인] 버튼 ② 사용자의 다음 말이 "응/네/맞아"(모델을 거치지 않고 로컬에서 확정) ③ 모델의 `confirm_pending_action` — 단, 대기를 만든 턴 이후이고 사용자의 마지막 말이 동의일 때만 통과. 모델이 혼자 확정하는 경로는 없음(테스트 [2][5][7]).
- 키가 없거나 설정에서 "대화 모드"를 끄면 예전 방식(규칙 기반 해석 + 확인 카드)으로 동작.
- 대화 기록은 최근 24개만 유지, 이 기기 메모리에만 있음.

### 2단계 — Gemini Live 실시간 대화 (베타, `루미 2단계` 블록)
- 대화 시트의 [🎙 실시간 대화] → WebSocket 연결, 마이크 16kHz PCM 전송, 24kHz PCM 재생, 끼어들면 즉시 멈춤, 같은 도구·같은 확인 규칙 사용(받아쓰기 기준으로 "응" 확인).
- 공식 문서의 예시가 모델명(`gemini-3.8-live`, `gemini-3.1-flash-live-preview`, `gemini-2.5-flash-native-audio-preview-12-2025`)과 setup 모양(`responseModalities` 를 setup 바로 아래 vs `generationConfig` 안)이 문서마다 달라서, 여러 조합을 차례로 시도하고 성공 조합을 `fp_live_ok` 에 기억. 설정 → 고급에서 모델을 직접 지정 가능.
- **실제 Google 서버에 연결해 본 적은 없음**(여기 환경에서 외부 접속 불가). 가짜 서버로 메시지 형식·재시도·도구 응답만 검증. 첫 실사용 때 연결 오류 문구에 시도한 조합이 표시됨.
- 키가 WebSocket 주소 쿼리(?key=)로 전달됨 → 가족 기기 전용으로만 사용. 공개 배포 시에는 임시 토큰/프록시 필요.

### 3단계 — 호출어 + 푸시
- **호출어(실험)**: 설정에서 켠 기기에서만, 앱이 화면에 떠 있을 때 SpeechRecognition(continuous)으로 이름("루미/로미/르미…")을 감지 → 효과음 → 이름 뒤 말이 있으면 바로 질의, 없으면 듣기 시작. 한계: 화면이 꺼지면 안 됨, 마이크 표시등 상시 켜짐, 안드로이드에서 재시작 "띵" 소리 가능. 진짜 상시 호출어(화면 꺼진 상태)는 웹 앱으로 불가 — 안드로이드 네이티브 앱(웨이크워드 엔진) 영역.
- **푸시(FCM)**: 클라이언트(기기 등록 → `families/{코드}/devices/{기기}`, 앞에서 토스트)와 `sw.js`(v4, 백그라운드 알림·클릭 처리)는 구현·모의 검증 완료. 서버 `functions/`(`notifyPrep`: 준비물 요청 생성 시 알림 켠 다른 기기에 전송, 죽은 토큰 정리)는 `node functions/test.js` 로직 검사만 통과. **배포는 직접**: Blaze 요금제 → VAPID 키 → `firebase deploy --only functions` → 기기에서 알림 켜기. 순서는 `docs/PUSH-SETUP.md`. ## 음성 끝 잡음·연속 호출 한도 대응 (v4.6)
- **끝에 "치직" 잡음**: Interactions 응답의 WAV 뒤에 data 조각이 아닌 다른 조각(LIST 등)이 붙어 있으면, `asDecodeAudio`가 파일 끝까지를 소리로 읽어 그 바이트가 잡음으로 재생됐다 → data 조각 크기만큼만 읽는다(`end`). 재생도 시작·끝 20~40ms 페이드(`asPlayPcm`의 GainNode)를 넣어 끝이 갑자기 끊기는 '틱'을 막는다. 실제 응답 구조는 실기기에서만 확인 가능(미검증).
- **연속으로 말시키면 기기 음성으로 바뀜**: 무료 구간의 분당 요청 한도(429)에 걸리는 것으로 추정(브리핑은 화자별로 여러 번 요청). → TTS 요청을 한 줄로 세우고(`_ttsQ`, 동시 1개) 429가 나면 서버가 알려 준 `RetryInfo.retryDelay`(최대 30초) 만큼 기다렸다가 한 번 더 시도(`asTtsFetch1`). 기다리는 동안 안내 문구가 뜨고, 그래도 429면 기기 음성으로 대신하며 사유를 알림에 표시. 같은 문장은 IndexedDB 캐시(`v2|목소리|해시`)를 써서 다시 요청하지 않는다. 한도는 키가 아니라 프로젝트 단위라 가든 앱 등 같은 프로젝트의 호출과 함께 센다.
- 테스트: `dev/assist-test.js [7d]`(WAV 뒤 조각 무시, 429 재시도, 동시 1개). 테스트용 `window.__AS_RETRY_MS`로 기다림을 줄인다.
- **벽걸이 딸 칸 잘림 수정(v4.6)**: `dev/members-test.js`의 "1280x800 한 화면에 잘림 없이 들어감"이 가끔 아니라 계속 실패했다(딸 칸이 12px 넘침: 루틴 줄바꿈 + 도구 버튼 줄). 1100px↑에서 `.w-kid .w-rt`/`.w-dd` 세로 여백을 줄이고 도구 버튼을 한 줄로(`nowrap`). 1280×800, 1138×712 모두 3칸 높이가 같아졌다(넘침 0).

## 한도(429)에 걸리면 기다리지 않고 기기 음성으로 (v4.7)
- v4.6의 "429면 알려 준 시간(최대 30초) 기다린 뒤 재시도"를 바꿨다(허남원님 요청): 기다리는 동안 소리가 없는 것보다 잠깐 기기 음성이 낫다. 429가 나면 즉시 실패시켜 기기 음성으로 읽고, `RetryInfo.retryDelay`(없으면 20초, 최대 60초) 동안은 Gemini에 요청을 보내지 않는다(`_ttsCool` 쿨다운). 쿨다운이 지나면 다음 문장부터 다시 Gemini 목소리로 돌아간다. 브리핑처럼 여러 구간이면 한도 구간은 기기 음성, 이후 구간은 Gemini 목소리가 섞일 수 있다. 요청은 계속 한 줄로 세운다.
- 테스트: `dev/assist-test.js [7d]`(429 즉시 실패, 쿨다운 중 요청 없음, 쿨다운 후 재개). 실제 한도 수치·실기기는 미검증.

- 변경(`buildStampView` 주변): 위쪽 `buildClockHeader()`(큰 시계 HH:MM 200 굵기, 날짜, `asLeaveText` 등교까지 N분, 브리핑·말하기 SVG 버튼, 동기화 배지·버전) + `fpClockTick()`(10초마다 글자만 갈아 끼움). `buildBriefCard()`는 "지금"(w.now 기온·상태)과 "오늘"(최저~최고, 강수 `popMax`, 등교 시간 `morn` 기온) 두 칸 + 옷차림·우산 칩 + 내일 한 줄. `buildLumiCard()`: 음성 구슬(`.orb` 버튼 → `asOpen('listen')`), "루미야 하고 불러 보세요"(호출어 켠 기기) 또는 "루미에게 말해 보세요", 질문하기·문제은행 버튼. `buildStampCard()`: 동그라미 10개(`STAMPS_PER_COUPON`, 채운 만큼 색), `7 / 10 · 누적 7개`, 도장 찍기 버튼(`stampFlow`), 보유 구입권 카드(`사용하기`)와 사용한 구입권 3개.
- 큰 도장 카드(`.hero`, `.ring`, `.pips`)와 옛 날씨 버튼 3개(`.bf-act`)는 삭제(루미 카드로 이동). 가로 태블릿 한 화면 그리드: 1열 날씨/루미/도장·구입권, 2열 루틴, 3열 수행평가(2행)/준비물. 다크 모드는 반투명 유리 카드(`rgba(255,255,255,.07)`+블러)와 은은한 빛 번짐(`.app-wrap:has(.home-fit)`), 라이트는 흰 카드.
- 한계: 날씨 아이콘(`w.now.icon`)은 데이터의 이모지 그대로(SVG 교체는 후속). 확인은 가짜 Firestore + 헤드리스 Chrome 캡처(1138×712, 1280×800, 390×844, 다크·라이트). 실기기 미검증.
